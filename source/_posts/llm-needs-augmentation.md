在第一节里说了，LLM其实只是一个经过海量数据训练而具有了智能的文本接龙机，所以它没有办法获得任何实时信息，或者说只能我们自己给它这些实时信息，它博览群书，也只博览群书。  
那么我们要怎么做才能让LLM知道这些呢？  
# 方式1：把信息塞进Prompt（朴素RAG）  
好听叫基于生物介质的实时信息传导，朴素就是我们自己在提示词里告诉它，这样简单粗暴，任何LLM都支持，但是你得手动决定传入啥并且不会撑爆上下文窗口，而且模型无法主动寻找需要的信息，就显得效率太低了  

那么还有什么方法吗？这里就到了Agent的雏形了  

# 方式2：让LLM自己调用工具  
{% asset_img 1.png LLM调用工具%}  
模型会主动去向外部世界获取信息，这里就是Agent的雏形了  

# 来对比一下这两种方式  
朴素RAG是人决定查什么，简单粗暴，喂信息；Tool Use是模型自己调用，这个需要实现工具调度  
实际工程里 往往是两种方式组合使用。用RAG把最相关的文档喂给LLM，同时让模型可以调用工具获得RAG没有覆盖的信息  

所以有  

```text
Agent -> LLM + Tool + How to choose
```  

于是Agent的开发流程就有了大致框架：  
1. 给LLM用啥工具  
2. 该如何让LLM正确选择工具  
3. 如何管理上下文不被撑爆  

好了，到这里已经知道了LLM是如何思考的，又是如何从LLM走向我们现在的多模态的，本期内容到此结束
